19  Package

Working notes on the R package API design and refactoring decisions. This chapter will be removed or reorganized once the refactor is merged.

19.1 Naming Conventions

Public-facing functions use dot notation to mirror base R (e.g., cor.test, cov):

  • ece.cov — equivariant covariance estimator (replaces equiv.cov)
  • ece.cor — equivariant correlation estimator (corresponds to cor)
  • ece.complexity — mean heterogeneity / complexity of the series
  • ece.se — asymptotic standard error of the correlation estimator
  • ece.test — hypothesis test for correlation (corresponds to cor.test)

Internal helpers use snake_case (e.g., ece_pair, var_corr_est).

19.2 Design Decisions

19.2.1 ece_pair (internal)

The internal workhorse for pairwise computation. Returns list(cov, complexity) for a single pair of vectors. Not exported. Pulled out of equiv.cov (formerly compute_equiv).

19.2.2 ece.cov

Mirrors the interface of base cov(): two vectors → scalar, matrix → p×p matrix. Calls ece_pair internally.

19.2.3 ece.complexity

Captures the slope of lagged differences as a function of lag. Large values indicate large or frequent mean shifts. Same interface as ece.cov.

19.2.4 ece.test

Accepts an n×2 matrix only (no Y = NULL). Dispatches on type:

  • type = "z.test" — asymptotic normal test based on ece.cor
  • type = "bs.multiplier" — multiplier bootstrap test (planned)

Returns list(estimate, p.value). conf.int was dropped as it was not functional.

19.2.5 var_corr_est

Now takes scalars (n, sx, sy, sxy, wx, wy, wxy) directly instead of an ece_obj. Renamed to ece.se at the public level.

20.1 Simulation

To evaluate ECE, we have produced many simulation scenarios.

# Generating Data
config <- scenario(1, n=1000)
X <- generate_data(config)
